# Sports Predictor

Flask/React sports prediction MVP with ESPN fixtures, structured injury data, weather context, SQLite history, and an explainable Elo + Poisson estimation engine.

The application is designed to produce a repeatable **match estimation result** for each fixture. It combines team ratings, home advantage, expected scoring rates, Poisson score distributions, and bounded live-factor adjustments. It is an estimation tool—not a guarantee or betting advice.

## Estimation engine

Predictions are generated by `predictor.py` through:

```python
predict_match(event, home_team, away_team, league=None, live_factors=None)
```

The engine follows this sequence:

1. Load a historical team Elo rating when one is available.
2. Use a deterministic fallback rating for unknown teams so the same matchup remains reproducible.
3. Apply the sport and league configuration, including home advantage and scoring averages.
4. Convert the rating difference into expected home and away scoring rates.
5. Apply bounded live adjustments:
   - injury penalties affect only the affected team;
   - soccer weather can reduce both scoring rates;
   - unavailable feeds remain neutral rather than inventing data.
6. Use Poisson distributions to calculate home-win, draw, and away-win probabilities.
7. Return the most likely outcome, projected score, confidence, model factors, and live-factor provenance.

The current model is configured for soccer and basketball in `SPORT_CONFIG`. Team ratings can be supplied through the configured ratings data; unknown teams use a stable name-based fallback rather than random values.

### Result fields

A successful `/api/predict` response includes the following engine output:

- `outcome`: the most likely result (`home`, `away`, or `Draw`, represented with team names where applicable).
- `home_win_probability`, `draw_probability`, `away_win_probability`: model probabilities between `0` and `1`.
- `projected_score`: rounded expected score for each team.
- `confidence`: percentage representation of the highest model probability; it is not a guarantee of accuracy.
- `model`: the engine label, currently `Elo + Poisson + live factors`.
- `factors`: ratings, rating sources, Elo difference, expected scores, league prior, and the live inputs used.
- `live_factors`: provider-backed injuries and weather data with source and timestamp fields.
- `updated_at`: UTC timestamp for the prediction.

## Production-safe environment

Copy `.env.example` to `.env` only for local development. Never commit `.env`, provider keys, database files, or deployment secrets. In production, configure the same variables through the hosting provider's secret/environment-variable settings.

Provider priority:

- Soccer injuries: API-Football when `API_FOOTBALL_KEY` is set; otherwise ESPN News fallback.
- Weather: WeatherAPI.com when `WEATHER_API_KEY` is set; otherwise Open-Meteo.
- Missing providers produce neutral, explicitly labeled factors. A prediction must never appear more certain merely because a provider is unavailable.

## Run and validate step-by-step

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

Validate the API in this order:

```bash
curl -i http://localhost:5000/api/health
curl -s http://localhost:5000/api/diagnostics
curl -s 'http://localhost:5000/api/fixtures?event=soccer'
curl -s 'http://localhost:5000/api/predict?event=soccer&fixture_id=soc-1'
curl -s 'http://localhost:5000/api/history?event=soccer'
```

Check that:

- health returns HTTP `200`;
- diagnostics never exposes secret values;
- fixtures contain `source` and `refreshed_at`;
- predictions contain `live_factors` with source and timestamp fields;
- predictions expose the Elo/Poisson `model`, probabilities, projected score, confidence, and `factors`;
- history contains saved predictions and their live-factor provenance.

### Example estimation request

```bash
curl -s 'http://localhost:5000/api/predict?event=soccer&fixture_id=soc-1' | python -m json.tool
```

Use the returned probabilities to compare the three possible outcomes, and use `projected_score` as the model's expected-score estimate. Always check `factors.live_factor_inputs` and `live_factors` before interpreting a result: provider status, source, and freshness indicate whether live context was available or neutral.

Run tests:

```bash
pytest
```

## Interpreting previous match estimates

For a new match, use the same engine workflow as previous predictions:

1. Select the fixture from `/api/fixtures`.
2. Request `/api/predict` with its `event` and `fixture_id`.
3. Record the returned `updated_at`, model probabilities, projected score, confidence, and factor sources.
4. Compare the result with `/api/history` after the match to evaluate calibration over time.

Do not compare confidence values across different sports or leagues without considering their configuration and draw behavior. A high confidence value means only that one modeled outcome is more probable than the alternatives under the current inputs; it does not account for every event that can affect a real match.
